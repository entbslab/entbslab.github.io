# 센터 홈페이지 운영 개요 (작동 방식 · 유지보수 · 비용 · 계정)

작성일: 2026-09-21 · 기준: 테스트 배포 상태 (https://screamingpeanut01.github.io/ku_entbs_page/)

---

## 1. 지금 어떻게 작동하는가

```
[담당자] GitHub 웹에서 site/data/content.js 수정 → Commit
    ↓ (자동, 1~2분)
[GitHub Actions] main 브랜치의 site/ 폴더를 gh-pages 브랜치로 복사
    ↓ (자동)
[GitHub Pages] gh-pages 브랜치를 그대로 웹에 공개 (HTTPS 포함)
    ↓
[방문자] 브라우저가 HTML/CSS/JS를 받아 화면에 그림
```

- 서버, 데이터베이스, 관리자 로그인 시스템이 없습니다. 파일만 있습니다.
- 페이지 6개(홈·소개·연구진·연구·소식·연락처)는 고정된 HTML이고, 공지·소식·연구진·성과·자료실 목록은 `content.js` 한 파일의 데이터를 읽어 브라우저에서 그립니다.
- 디자인은 `assets/style.css`, 공통 메뉴·푸터는 `assets/main.js` 하나에서 관리합니다.
- 저장소에 모든 변경 이력이 남으므로 어떤 수정도 되돌릴 수 있습니다.

## 2. 유지보수는 어떻게 하는가

| 작업 | 누가 | 방법 | 소요 |
|---|---|---|---|
| 공지·소식·자료 추가 | 조교 | GitHub 웹에서 `content.js` 편집 → Commit | 3분 |
| 연구진 추가·수정 | 조교 | 같은 파일의 `members` 배열 수정 | 3분 |
| PDF·사진 업로드 | 조교 | `site/assets/`에 Upload files → `content.js`에서 경로 연결 | 5분 |
| 문구·메뉴명 변경 | 조교 | `content.js`의 `nav`, `tagline` 등 수정 | 3분 |
| 디자인·레이아웃 변경 | 개발 가능자 | `style.css`, 각 HTML 수정. 별도 브랜치에서 작업 후 병합 권장 | 건별 |
| 장애 확인 | 조교 | 저장소 Actions 탭에 빨간 X → 대부분 쉼표·따옴표 누락. 이전 커밋으로 Revert | 5분 |
| 연 1회 점검 | 담당자 | 도메인 만료일 확인, Code → Download ZIP 백업, 관리자 계정 정리 | 30분 |

**업데이트나 패치가 필요한 소프트웨어가 없습니다.** 프레임워크·플러그인·서버 OS가 없으므로 보안 업데이트, 버전 호환 문제, "PHP 지원 종료" 같은 이슈가 생기지 않습니다. 워크플로우가 쓰는 GitHub 액션 2개는 몇 년에 한 번 버전 숫자만 올리면 됩니다.

**콘텐츠 편집 난이도**: 텍스트 파일에서 `{ date: "...", title: "..." }` 블록을 복사해 값을 바꾸는 수준입니다. 부담스러우면 구글 시트 연동(6절) 또는 관리 화면(Decap CMS) 추가로 낮출 수 있습니다.

## 3. 비용

| 항목 | 현재 | 정식 운영 시 |
|---|---|---|
| 호스팅 (GitHub Pages) | 0원 | 0원 |
| 자동 배포 (GitHub Actions) | 0원 | 0원 (공개 저장소는 무제한) |
| SSL 인증서 | 0원 (자동) | 0원 |
| 도메인 (.com) | 없음 | 연 약 24,000원 (가비아) 또는 약 $11 (Cloudflare) |
| 구글 시트 연동 (선택) | – | 0원 |
| 관리 화면 Decap CMS (선택) | – | 0원 |
| **합계** | **0원** | **연 약 1.5만~3만원 (도메인만)** |

GitHub Pages 무료 조건: 공개 저장소, 사이트 용량 1GB 이하, 월 대역폭 100GB 소프트 리밋, 시간당 빌드 10회. 연구센터 규모에서는 도달할 일이 없습니다.

비교: Wix Light 연 약 30만원, vibeX Pro 연 약 55만원 이상. 둘 다 결제가 끊기면 사이트가 내려가지만, 현재 방식은 도메인 결제를 놓쳐도 `github.io` 주소로는 계속 접속됩니다.

## 4. 필요한 계정

### 필수
| 계정 | 용도 | 누가 | 비고 |
|---|---|---|---|
| GitHub 계정 (저장소 소유) | 사이트 파일 보관, 배포 | **센터 명의 Organization 권장** (예: `ku-cesm`) | 현재는 개인 계정 `screamingpeanut01` 소유. 담당자가 졸업·이동해도 사이트가 남도록 Organization으로 이관 필요. Organization 생성 무료 |
| GitHub 계정 (관리자) | 콘텐츠 편집 | 교수님(Admin), 조교(Write) | 각자 개인 GitHub 계정을 만들고 저장소에 collaborator로 추가. 무료 |

### 정식 도메인 사용 시
| 계정 | 용도 | 누가 | 비고 |
|---|---|---|---|
| 도메인 등록업체 (가비아 등) | 도메인 구매·DNS 설정·매년 갱신 | 센터 명의, 결제는 센터 운영비 | 자동 갱신 켜기. 만료 알림 이메일은 여러 명이 받도록 설정 |

### 선택
| 계정 | 용도 | 비고 |
|---|---|---|
| 구글 계정 (시트 연동 시) | 공지 입력용 시트 소유 | 센터 공용 구글 계정 또는 교수님 계정. 조교는 시트 편집 권한만 받음 |
| Cloudflare 계정 | 대역폭 무제한·DDoS 보호가 필요해질 때 이전 | 지금은 불필요 |

### 필요 없는 것
- 서버·호스팅 결제 계정, 관리자 비밀번호 시스템, 워드프레스 같은 CMS 계정, 개발 도구 설치

## 5. 인수인계 시 넘겨야 할 것
1. GitHub Organization 소유자 권한 (또는 저장소 Admin 권한)
2. 도메인 등록업체 로그인 정보와 갱신일
3. (연동 시) 구글 시트 소유권
4. `docs/OPERATIONS.md` 링크

이 4가지만 넘기면 새 담당자가 당일 운영을 이어갈 수 있습니다.

## 6. 구글 시트 연동을 추가하면 달라지는 것

| | 현재 (content.js 편집) | 시트 연동 후 |
|---|---|---|
| 공지 추가 | GitHub 웹에서 코드 블록 복사·수정 → Commit | 구글 시트에 한 줄 입력 |
| 반영 시간 | 1~2분 | 약 5분 (시트 "웹에 게시" 방식) |
| 필요한 계정 | GitHub | GitHub + 구글 (조교는 구글만 있어도 됨) |
| 실수 위험 | 쉼표·따옴표 누락으로 페이지가 깨질 수 있음 | 시트라 문법 오류 없음. 날짜 형식만 지키면 됨 |
| 비용 | 0원 | 0원 |
| 의존성 | GitHub | GitHub + 구글 (구글 장애 시 목록이 늦게 뜸) |

권장 구성: 공지·소식·연구진·성과·자료실 목록은 시트에서, 소개문·인사말·연락처처럼 거의 안 바뀌는 내용은 지금처럼 파일에서 관리.

## 7. 알아둘 리스크

- **개인 계정 소유**: 가장 큰 리스크. Organization 이관으로 해결 (10분 작업).
- **공개 저장소**: 사이트 원본과 편집 이력이 누구에게나 보입니다. 공개 홈페이지이므로 문제는 없지만, 비공개 문서·개인정보를 저장소에 올리면 안 됩니다.
- **GitHub 정책 변경**: Pages가 유료화될 가능성은 낮지만, 그 경우 `site/` 폴더를 Cloudflare Pages나 Netlify에 그대로 옮기면 됩니다. 락인이 없습니다.
- **`content.js` 문법 오류**: 페이지가 흰 화면이 됩니다. Revert로 즉시 복구되며, 시트 연동 시 사라지는 문제입니다.
