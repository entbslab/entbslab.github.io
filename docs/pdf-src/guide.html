01

홈페이지 구성

홈페이지의 모든 내용은 GitHub의 "홈페이지 저장소" 한 곳에 들어 있고, 나머지는 그것을 보여주거나 고치도록 돕는 역할입니다.

구성하는 일위치

호스팅홈페이지를 인터넷에 공개GitHub Pages (무료)
로그인 중계 서버관리자 화면의 "GitHub로 로그인"을 처리Cloudflare, 김권택 개인 계정

02

공지가 올라가는 과정

관리자가 저장 버튼만 누르면 나머지는 자동으로 처리되고, 1~2분 뒤 홈페이지에 나타납니다.

  • GitHub 조직에 초대받은 사람만 저장할 수 있습니다.
  • 모든 수정이 기록으로 남아, 잘못 고친 내용도 이전 상태로 되돌릴 수 있습니다.

관리자 화면에서 바꿀 수 있는 것

관리자 화면 메뉴내용
공지사항 · 자료실추가·수정·삭제, 사진·첨부파일
연구진이름, 소속, 사진, 표시 순서
성과 (프로젝트·논문·세미나·소식)추가·수정·삭제. 홈페이지 PERFORMANCE 한 페이지에 모여서 표시
소개 · 설정센터 소개문, 센터장 인사말, 연락처, 지도, 메뉴 이름, 로고, 홈 배너 사진(여러 장 가능)

새 페이지를 만들거나 디자인·배치를 바꾸는 일은 관리자 화면으로는 할 수 없고, 코딩이 가능한 사람이 저장소를 수정해야 합니다.

04

평소 관리

평소에는 조교가 관리자 화면에서 내용을 올리는 것이 전부이며, 1년에 한 번 30분 정도 점검하면 됩니다. 프로그램 업데이트나 서버 관리는 필요하지 않습니다.

주기할 일담당
수시공지·소식·자료 등록, 연구진·논문 갱신 (건당 약 2분)조교
수시소개문·인사말·연락처·배너 사진 변경조교
인원 변동 시새 조교를 GitHub 조직에 초대, 떠난 사람 제거Owner
필요 시새 메뉴·페이지 추가, 디자인 변경코딩 가능자
연 1회졸업한 조교 제거, Owner가 2명 이상인지 확인담당자
연 1회홈페이지 저장소 전체를 내려받아 센터 드라이브에 백업담당자

문제가 생겼을 때

증상원인조치
저장했는데 홈페이지에 반영되지 않음방금 저장한 내용에 오류직전 수정을 되돌리기 (수정 기록에서 몇 번의 클릭)
"데이터를 불러오지 못했습니다" 표시최근 바꾼 내용이 손상됨직전 수정을 되돌리기
"GitHub로 로그인"이 안 됨로그인 중계 서버(Cloudflare) 문제담당자가 Cloudflare 확인. 급하면 개인 인증키로 로그인
로그인은 되는데 저장이 안 됨GitHub 조직에 초대되지 않은 계정Owner가 해당 계정을 초대

어떤 문제가 생겨도 방문자가 보는 홈페이지는 마지막으로 정상이던 상태로 계속 열려 있습니다. 담당자용 상세 절차는 저장소 docs 폴더의 운영 가이드(OPERATIONS.md)와 관리자 화면 설정 문서(ADMIN_SETUP.md)에 있습니다.

05

인수인계

홈페이지 파일은 이미 GitHub 조직에 있어 옮길 것이 없고, GitHub 조직과 Cloudflare 두 곳의 관리 권한만 넘기면 됩니다. 하루면 충분합니다.

인수인계 체크리스트

  • 후임자의 GitHub 계정을 GitHub 조직에 초대하고, 후임자가 수락했는지 확인
  • Owner가 항상 2명 이상인지 확인 (교수님 + 담당자)
  • Cloudflare에 후임자를 관리자로 초대 (또는 후임자 계정에 로그인 중계 서버를 새로 설치, 약 20분)
  • 후임자가 관리자 화면에서 공지 1건을 올려 홈페이지에 나타나는지 확인
  • 이 가이드와 저장소 docs 폴더의 위치를 후임자에게 전달
  • 전임자를 GitHub 조직과 Cloudflare에서 제거

로그인 중계 서버를 후임자 계정에 새로 설치하는 경우에만 설정 두 곳을 수정하는 작업이 추가됩니다. 절차는 저장소 docs 폴더의 관리자 화면 설정 문서(ADMIN_SETUP.md)에 있습니다.
